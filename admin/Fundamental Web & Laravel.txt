Kenapa struktur ini menurut saya lebih baik?

Karena ada dua jenis pengetahuan yang berbeda.

1. Pengetahuan yang relatif tahan lama

Misalnya:

MVC
Routing
Controller
Request/Response
Middleware
Eloquent
Database
Validation
Authentication
Authorization
Service Container
Dependency Injection
Queue
Events
Testing
API
Architecture

Konsep-konsep ini tidak seharusnya diajarkan sebagai “fitur Laravel 13”.

Kalau tahun depan Laravel 14 keluar, pembaca tetap memahami konsepnya.

2. Pengetahuan yang version-specific

Misalnya:

fitur baru Laravel 13
perubahan API
breaking changes
AI SDK
JSON:API resources
semantic/vector search
perubahan Inertia
perubahan starter kits
perubahan deployment ecosystem

Ini yang kita masukkan ke bagian khusus Laravel 13.

Dengan demikian, buku memiliki umur yang jauh lebih panjang.

Bahkan saya akan membuat judul bukunya seperti ini

Bukan:

❌ Laravel 13: Panduan Lengkap Laravel

Karena judul seperti itu membuat buku terlalu terikat pada satu versi.

Saya lebih menyukai:

Laravel Modern — Panduan Lengkap dari Fundamental hingga Advanced
Berbasis Laravel 13

atau:

Mastering Laravel
Dari Fundamental, Arsitektur, hingga Laravel 13

atau kalau ingin lebih teknis:

Laravel 13: From Fundamentals to Professional Application Development

Subjudul bisa menjelaskan:

Panduan Mendalam Membangun Aplikasi Web, REST API, Real-Time Application, AI Application, hingga Production-Grade Laravel.

Dan ada satu prinsip penting untuk penulisan buku ini

Saya sarankan jangan menjadikan nomor versi sebagai pusat buku.

Contohnya, jangan:

Bab 12 — Laravel 13 Eloquent

Lebih baik:

Bab 13 — Eloquent ORM
Catatan Laravel 13: fitur/perubahan terbaru

Jadi isi utama:

13.1 Apa itu ORM
13.2 Apa itu Eloquent
13.3 Model
13.4 CRUD
13.5 Mass Assignment
13.6 Casting
13.7 Accessor & Mutator
13.8 Relationships
...

Kemudian jika ada fitur khusus Laravel 13:

┌─────────────────────────────────────────────┐
│ LARAVEL 13 NOTE                             │
│                                             │
│ Bagian ini menjelaskan fitur/perubahan      │
│ yang diperkenalkan atau diperbarui pada     │
│ Laravel 13.                                 │
└─────────────────────────────────────────────┘

Dengan pola ini, 80–90% buku tetap relevan ketika Laravel 14/15 keluar, sementara bagian “Laravel 13” bisa diperbarui tanpa harus menulis ulang seluruh buku.

Dan menurut saya ini sangat cocok dengan kondisi sekarang: dokumentasi resmi Laravel 13 sendiri memisahkan Getting Started, Architecture Concepts, The Basics, Database, Eloquent, Testing, dan seterusnya, sementara fitur baru seperti AI dan JSON:API berada di atas fondasi tersebut.

Jadi keputusan editorial saya: Fundamental → Core Laravel → Professional Laravel → Laravel 13 & modern ecosystem → Advanced/Production → Projects. Ini jauh lebih kuat daripada membuat seluruh buku sebagai dokumentasi Laravel 13.
